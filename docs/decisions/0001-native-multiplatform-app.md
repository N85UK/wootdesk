# ADR 0001: Native Multiplatform SwiftUI App Target

## Context
WootDesk is designed to run on macOS, iOS, and iPadOS. We evaluated three architectural approaches:
1. **Web Wrapper / Electron / PWA:** Wrapping the existing Chatwoot web interface in a web view.
2. **Mac Catalyst:** Building an iPadOS application and porting it to macOS using Catalyst.
3. **Native Multiplatform SwiftUI App Target:** Sharing domain, networking, persistence, and UI logic across macOS and iOS while applying platform-tailored SwiftUI navigation idioms.

## Decision
We chose a **Native Multiplatform SwiftUI architecture** using a single multiplatform Xcode target.

## Consequences & Rationale
- **Performance and Energy:** A native SwiftUI list avoids shipping a browser engine, which is the main cost of an Electron or web-view wrapper. No benchmark has been taken yet, so this milestone makes no numeric performance claim.
- **Mac User Experience:** Native split views, sidebars, keyboard shortcuts, and menu commands are available directly, which a wrapped web interface cannot offer.
- **Shared Codebase:** The whole `Core` layer (models, API client, persistence, security, logging) and all feature state types are shared unchanged. Platform-specific code is confined to the navigation shells: a three-column `NavigationSplitView` on macOS and a `TabView` of `NavigationStack`s on iOS, plus a small number of `#if os(...)` branches in the conversation list.
- **Strict Concurrency:** Compatible with Swift 6 language mode and the Observation framework.

## Costs Accepted
- Two navigation shells must be maintained and tested separately.
- macOS UI tests need a signed test runner, so they are opt-in rather than part of the default CI run.
- The project is generated by XcodeGen from `project.yml`, so target and entitlement changes must be made there rather than in the Xcode UI, or they will be overwritten on the next generation.
